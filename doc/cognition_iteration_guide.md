# Cognition 迭代指南

## 认知层的定位

Cognition 存储的是角色对**人、关系、自我、长期事物**的稳定认知。

它与周边模块的分界：
- **memory**（记忆层）：存储"发生了什么"——具体事件
- **cognition**（认知层）：存储"某人是怎样的"——从事件中沉淀的稳定理解
- **emotion**（情绪层）：存储"现在感觉如何"——短期状态

## 迭代验证方法

### 1. 多轮后检查 cognition 输出

在 `text_cli.py` 中聊 10-15 轮后，查看 `characters/{id}/cognition.json`：

```json
{
  "entries": {
    "自己": "知性冷静，说话有条理且用词考究...",
    "真冬": "日常使用的称呼，不是爱丽丝的真实对象...",
    "真冬和自己的关系": "日常相处关系",
    "蓬莱": "自己制作的人偶，有独立说话风格..."
  }
}
```

检查项：
- 不同人是否有独立的 key（不要都写成"用户"）
- value 是稳定印象，不是事件流水账
- 不存在带括号的临时 key

### 2. 检查 key 匹配性

`cognition.refresh_cache()` 在每轮对话后做关键词匹配。验证：

```
对话中说"真冬今天的咖啡..."
→ 应该匹配 key "真冬"
→ 应该匹配 key "真冬和自己的关系"
→ 不应该匹配不相关 key
```

### 3. 检查破坏性保护

`_looks_destructive()` 检查：如果 cognition 评估结果大幅缩水（< 1/3 条目数），且关键条目丢失，则拒绝更新。

测试方法：在聊天中导入大量临时信息后做 cognition 评估，确认已有稳定条目不被冲掉。

## 常见问题与排查

### "把不同人混成了用户/对方"
检查 `evaluate_user` 提示词中的"批量实体要求"部分是否生效。如果 key 变成了"用户""对方""观众"而不是具体名字，需要检查 LLM 输出。

修复方向：cognition.evaluate 的 system prompt 中强化"不同参与者必须保持可区分"指令。

### "把事件直接写成性格总结"
对比 cognition.json 的描述和同段对话的 memory_events 提取结果。如果 cognition 里出现了事件原文而非人物印象概括，说明 extract 和 cognition 的边界还需要拉清。

### "丢失参与者名字"
检查 `evaluate_user` 提示词中的"对象锚点要求"部分。如果 context 里有多个人的名字但 cognition 输出只保留了"用户"，可能需要增加 prompt 中关于批量实体的检查力度。

### "写入临时屏幕内容"
cognition 提示词已禁止写入当前页面、今天计划等临时内容。如果出现，检查 `evaluate` 触发时机——全量评估只在摘要后和每 N 轮触发，不应该每轮都写。

## 测试场景

```text
场景 A：多人物聊天
  用户介绍了三个朋友 → 检查 cognition 是否有三个独立 key

场景 B：长期兴趣沉淀
  连续 N 轮聊哲学 → 检查 cognition 是否沉淀了"对哲学有兴趣"
  切换到其他话题后 → 检查该条目是否保留（不因不提到就删除）

场景 C：破坏性测试
  发一条清空提示 → 检查 _looks_destructive 是否阻止清空
```
