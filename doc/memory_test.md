# 记忆测试

## 测试目标

验证三件事：

1. **写入成功**：对话后记忆是否确实被存储
2. **检索命中**：后续提到相关内容时是否能召回
3. **事件化质量**：记忆存的是具体事件不是空泛印象

## 最小验证场景

### 写入验证

```text
用户: "我昨天第一次做了咖啡拉花，虽然不太成功但还挺好玩的。"
  → 聊几轮其他话题
  → 重启程序
  → 检查 cognition.json 或 memory_viewer.py
```

预期：记忆中存在关于"咖啡拉花"的事件条目。

### 检索验证

```text
用户: "你觉得我最近还有什么新爱好值得试试？"
```

预期：LLM 的回复中提及咖啡拉花（如果召回成功）。

### 事件化质量

```text
memory_viewer.py 查看记忆内容
```

预期：看到的是"真冬做了咖啡拉花，第一次尝试不太成功但觉得好玩"这类具体描述，而不是"喜欢尝试新事物"这类空泛概括。

## 验证工具

```bash
# 记忆查看器（推荐）
python memory_viewer.py

# 文本模式 + 记忆
python text_cli.py --no-cognition --no-store

# 完整模式观察记忆行为
python text_cli.py
```

### memory_viewer.py 用法

打开后可以看到：
- 每个角色的记忆列表
- 记忆内容和相似度分数
- 创建时间
- 可按关键词搜索
- 可删除单条或全部清空

## 注意事项

### 关于 Windows 控制台编码

Windows 非 UTF-8 控制台可能把中文显示为 `?`，这不等于记忆损坏。解决方法：

1. 优先使用 `memory_viewer.py`（GUI 版本）
2. 或在 UTF-8 终端（如 Windows Terminal）中运行

### 关于 mem0 的阈值

`search_threshold` 默认 0.2。如果检索不到记忆，可以试试：

```toml
[mem0.lifecycle]
search_threshold = 0.15  # 适当降低阈值
search_top_k = 16        # 增加召回数量
```

### 关于记忆漂移

长对话中如果发现记忆质量下降（召回了不相关内容），检查：
- `compress_interval` 是否触发（默认 50 次存储）
- 是否有过多低质量记忆未被过滤
- 是否打开了 `importance_mode = "auto"` 让 LLM 过滤

## 回归测试建议

```text
1. 说一段具体事件（10 字以上）
2. 聊 5-10 轮无关话题
3. 用核心实体词提问
4. (可选) 重启程序后再问一次，验证持久化
5. 用 memory_viewer.py 查看实际存储内容
```
