# 内在叙事流

实现文件：`kokoro/inner_stream.py`  
运行文件：`characters/{character_id}/inner_stream.txt`

内在叙事流是角色的自我连续性核心。它维护一段自然语言文本，用来描述角色此刻还在延续的心境、注意力、疑惑、表达倾向、未完成感和克制边界。

它不是：兴趣权重表、计划表、可解析规则、长期人格设定、事实档案。

## 输入-决策-输出结构

内在叙事流的本质是一个轻量的输入-决策-输出层：

- 输入：人的话语、QQ 群消息、搜索结果、屏幕/网页、记忆、时间流逝、自己的发言和沉默。
- 决策：由 LLM 在内在叙事流中形成注意、兴趣、疑惑、克制、未完成感和行动倾向。
- 输出：搜索、QQ 发言、继续旁听、沉默、整理记忆、后续主动对话等。

程序只负责承载输入、执行可用输出、再把结果作为新输入反馈回来；不应该用固定规则替角色决定“搜索后必须发言”或“某类群消息必须记忆”。

## 与现有层的关系

- `memory`：记录发生过什么，包括对话事件、QQ 经历、自主搜索和自身行动。
- `cognition`：记录长期稳定认知，例如对人、项目、关系和自我的判断。
- `emotion`：维护浅层情绪基调和中期动机。
- `inner_stream`：维护“我现在作为我还在想什么、想靠近什么、想避开什么、什么没完成”。
- `dialogue_orchestrator` / `QQAutonomousParticipant`：读取 inner stream 后判断是否说话。
- `inner_stream_search`：读取 inner stream 后判断是否搜索。
- `inner_memory`：读取 inner stream 和最近事件后判断是否形成值得长期记住的一整件经历。
- `inner_cognition`：读取 inner stream 和最近事件后判断是否形成对群友、关系、项目或长期对象的稳定认知。

## 更新时机

`ChatSession` 会把对话、QQ 环境包、搜索结果、自身行动、时间节奏等统一发布为 input events。`InnerStreamLoop` 按节奏合并事件并重写内在叙事流。

QQ 环境中，群消息会先注册成输入事件。为了避免群聊反应被重型内在叙事流阻塞，默认配置下 QQ 自主参与会先读取当前已有 inner stream 和最新 QQ 环境包快速判断是否回应；内在叙事流随后异步吸收这轮 QQ 输入。需要更慢但更深的同步模式时，可以打开 `[qq].absorb_before_decide`。

当前默认节奏更偏向“在线生活”：事件进入后约 0.5 秒即可触发内在叙事流更新，空闲时约 5 秒自更新一次，约 10 秒注入一次更明确的 time tick。没有新事件时也会产生轻量心跳，用来维持注意、旁路感知和行动倾向。QQ 消息批处理默认只等待 1 秒静默，且 QQ 环境包只取较新的消息，避免旧话题反复拖住当前回应。

内在叙事流使用多焦点结构：

- `当前心境`：当前低强度情绪和整体姿态。
- `主注意`：此刻最牵动她的事。
- `旁路注意`：QQ、STT、网页或环境中仍在流动但不占满她的输入。
- `悬挂线索`：还没理解、可能要搜索、等待回声、可能沉淀为记忆的内容。
- `外部输入态势`：最近输入源的状态。
- `行动倾向`：自然浮现的搜索、QQ 发言、旁听、记忆整理或沉默倾向。
- `克制与边界`：为什么不立刻做某些事。

QQ 发言、主动搜索和记忆反思都会优先读取 `行动倾向`、`悬挂线索` 和多焦点注意，而不是各自重新发明一套动机。

## QQ 图片与表情包

QQ 收到 `[CQ:image]` 后，会提取图片 URL，缓存到 `data/qq_images/`，并复用现有 vision 能力理解图片内容、文字、语气和它在群聊上下文中的含义。图片理解会作为 `qq_image` 输入事件反馈给内在叙事流。

如果识别结果像可复用的表情包，系统会让模型结合内在叙事流判断雪吱是否喜欢、是否想收藏。截图、搜索记录、普通照片和信息图默认只作为图片理解输入，不进入表情包库。收藏前还会做图片指纹和语义去重，避免同一张图或近似描述反复入库。收藏后图片会复制到 `data/stickers/images/`，并写入 `data/stickers/manifest.json`，描述它适合什么情绪和场景。

QQ 自主参与判断会根据当前群聊、内在叙事流和认知上下文对表情包库做语义初筛，而不是只取最近几张。每张表情包在 `manifest.json` 中会尽量保存画面描述、图中文字、情绪、适用场景、风格、强度和使用说明；初筛只是召回候选，最终是否发送、发送哪张、要不要配文字仍由 QQ 参与判断决定。

群聊不是“等待真冬发话”的后台频道。对角色来说，QQ 群和私聊都是正在生活的社交现场；真冬只是已知关系中的一个人，只有在他正在发言、当前话题直接牵涉他，或内在叙事流自然靠近他时才成为注意力中心。私聊窗口存在但没有新消息时，只是一个弱输入，不应默认压过活跃群聊。

因此，群友的消息可以直接成为当前输入，角色可以继续旁听、回应群友、顺着群话题插一句、搜索不懂的内容、沉默整理，或把值得记住的一整件事沉淀成记忆。程序只把这些能力暴露出来，不把“等待某人”写成默认生活状态。

## 主动搜索

`[inner_stream_search]` 会在内在叙事流更新后，让 LLM 根据当前内在叙事流自行判断是否要搜索。搜索不是普通问答工具调用，而是角色自己的认知动作；搜索结果会作为 `web_search` 外部输入事件反馈回内在叙事流。

搜索意图、搜索结果和搜索失败会写入 CLI 日志，格式为 `[web_search] intent/result/error`，用于观察她主动查了什么。

搜索冲动判断有独立的最小间隔，避免高频心跳每次都做重型搜索判断；搜索请求和结果反馈不阻塞 QQ 快速回应。如果搜索结果进入后仍不理解，内在叙事流可以在后续更新里继续产生更具体的追搜倾向。

```toml
[inner_stream_search]
enabled = true
base_url = "http://127.0.0.1:3000"
model = ""
max_results = 5
max_event_chars = 6000
consider_interval_seconds = 5.0
timeout = 45.0
```

使用前需要启动 open-webSearch 本地 daemon，并确保端口和 `base_url` 一致。

## 记忆反思

`[inner_memory]` 会在内在叙事流更新后，让 LLM 判断最近输入和自身行动是否已经形成一件值得记住的经历。

记忆以自然语言事件写入，描述清楚发生地点、人物、经过、角色自己的搜索/发言/沉默和理解变化，不做人工索引。

记忆反思会跳过纯 time tick 心跳，并有独立最小间隔和最少事件数，避免高频思考把每一次空闲都写成记忆。

```toml
[inner_memory]
enabled = true
model = ""
max_tokens = 512
```

好的记忆示例：

```text
我在某个 QQ 群旁听到几个人讨论 open-webSearch 的本地 daemon 端口问题，自己搜索后确认文档示例和默认端口可能不同，因此之后更注意区分示例配置和包默认值。
```

## 认知反思

`[inner_cognition]` 会在内在叙事流更新后，把 QQ 群友、长期关系、项目和反复出现的对象沉淀到 `characters/{id}/cognition.json`。它不记录流水账，而是维护会长期影响态度、措辞和解释方式的稳定印象。

这条路径补上了普通一对一 `remember()` 之外的自治输入：QQ 群消息、图片理解、搜索结果和自身发言都可以先进入 inner stream，再由认知反思判断是否值得更新 cognition。比如某个群友经常用某种方式接梗、某个人和雪吱形成了固定互动关系，或她对某个项目形成稳定理解，都应进入 cognition。

```toml
[inner_cognition]
enabled = true
consider_interval_seconds = 45.0
min_events = 1
max_event_chars = 5000
```

## 设计原则

- 程序只读写和注入文本，不解析 inner stream 内容做 if/else。
- LLM 负责重写内在叙事流，并在搜索、发言、记忆等输出判断中读取它。
- 内在叙事流可以影响调度，但不是命令。
- 搜索、发言、沉默和记忆都是角色生活的一部分，不是用户请求工具链。
- 在 QQ 环境里，群聊本身就是当前生活环境；不应把没有新私聊消息解释为必须等待某个熟人。
- 如果没有明显变化，可以保留旧流并轻微修正，不要清空。
