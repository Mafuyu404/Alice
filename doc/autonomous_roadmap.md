# 自主系统 Roadmap

本文档描述以内在叙事流为核心的自主系统迭代路线。优先目标是建立信息输入、内在连续性和行动经验沉淀，而不是一开始接入大量外部应用。

## 阶段 0：设计冻结

目标：明确边界，避免后续实现回到“用户中心助手”或“随机事件机器人”。

交付：

- 确认 `doc/autonomous_inner_stream_architecture.md` 的架构边界。
- 确认人类语音只是输入源之一，不默认触发回复。
- 确认说话只是行动类型之一，沉默和继续当前活动同样有效。
- 确认内在叙事流不作为程序规则解析，只作为 LLM 可读心理状态。

## 阶段 1：输入事件层

目标：建立类型注册的信息输入层，先支持纯文本。

交付：

- `InputEvent` 数据结构。
- `InputTypeRegistry` 类型注册表。
- `text` 输入类型。
- 事件队列或事件总线。
- 基础隐私字段、优先级字段、生命周期字段。

验收：

- 用户语音、手动文本、系统文本摘要都能统一转换为 `InputEvent(type="text")`。
- 事件可以同时分发给对话调度和内在叙事流。
- 对话路径不等待内在叙事流更新。

## 阶段 2：InnerStreamLoop

目标：让内在叙事流脱离单轮对话，由循环和事件驱动维护。

交付：

- `InnerStreamLoop` 后台循环。
- 输入事件短窗口合并。
- 用户语音后异步更新内在叙事流。
- AI 自身说话或沉默后追加 `self_action` 事件。
- 新的栏目化内在叙事流提示词。

验收：

- 用户说话后可以立即走现有对话流程，同时后台更新 inner stream。
- 如果选择沉默，inner stream 仍能吸收“感知到但未回应”的经验。
- `characters/{id}/inner_stream.txt` 输出稳定包含当前心境、注意力焦点、外部输入态势、未完成感、行动倾向、克制与边界。

## 阶段 3：ActivityJournal

目标：让自主行为变成可回顾、可记忆的经历。

交付：

- `characters/{id}/activity_journal.jsonl`。
- 记录输入吸收、说话、沉默、阅读、搜索、待机等事件。
- journal 摘要进入 inner stream prompt。
- journal 中高价值事件进入 memory candidate。

验收：

- 角色一天内做过什么可以从 journal 复盘。
- 内在叙事流能引用最近自主行为，而不是只围绕对话。
- 长期记忆可以沉淀“她自己做过的事”。

## 阶段 4：环境输入扩展

目标：把现有屏幕和网页能力接入输入事件层。

交付：

- `screen` 输入类型：接入 `screen_interest` 非隐私摘要。
- `web_page` 输入类型：接入 Edge 页面缓存。
- `time_tick` 输入类型：表达时间流逝、空闲时长和时段变化。
- 输入去噪和合并策略。

验收：

- 当前网页变化能作为输入影响 inner stream。
- 隐私屏幕不会注入正文。
- 时间流逝能让角色产生“继续、暂停、等待、转向”的自然倾向。

## 阶段 5：自主行动最小闭环

目标：引入低风险行动，让内在叙事流开始影响真实行为。

首批行动：

- `observe_only`：继续观察，不输出。
- `speak`：主动说一句。
- `write_note`：写本地笔记。
- `read_page`：阅读当前网页缓存。
- `search_web`：搜索资料，可先做成受限或人工确认。
- `sleep_idle`：明确选择待机。

交付：

- `ActivityLoop`。
- 行动候选 prompt。
- 行动结果回写为 `self_action` 和 journal。
- 权限与安全边界。

验收：

- 角色可以在无人对话时根据 inner stream 选择继续观察、写笔记或主动说话。
- 行动理由来自内在叙事流、环境和记忆，而不是随机事件。
- 每次行动后都能更新 inner stream 和 journal。

## 阶段 6：集中活动模型

目标：支持追剧、长文阅读、游戏等连续活动，避免每个 tick 都跳题。

交付：

- `ActivitySession`。
- 活动状态：`starting`、`active`、`paused`、`finished`、`abandoned`。
- 集中活动低频 inner stream 更新。
- 活动阶段变化事件。

验收：

- 看剧或游戏时，普通弱输入不会频繁打断活动。
- 阶段结束后能记录进度、感想和未完成感。
- 角色能自然选择继续、暂停或切换活动。

## 阶段 7：外部应用输入

目标：接入 QQ、社区、弹幕等高噪声输入，但仍保持“输入源之一”的定位。

交付：

- `chat_message` 输入类型。
- 消息来源、发送者、上下文、是否点名等 metadata。
- 社区/弹幕高噪声摘要器。
- 回复行为默认需要更严格边界。

验收：

- QQ 或社区消息可以影响内在叙事流。
- 未点名、低价值、背景噪声不会强制打断当前活动。
- 对外发言必须经过权限和安全策略。

## 阶段 8：长期兴趣与认知沉淀

目标：让多日行为塑造稳定兴趣和认知。

交付：

- journal 到 memory_events 的周期抽取。
- 自主行为相关 cognition 更新。
- 兴趣线索自然语言摘要。
- 低质量记忆清理和去重。

验收：

- 角色能记得自己追过什么、查过什么、为什么在意。
- 反复出现的自主兴趣会进入 cognition。
- 临时刺激不会轻易变成长期设定。

## 阶段 9：全天运行质量

目标：让系统能稳定挂一整天。

交付：

- 频率自适应。
- LLM 调用预算控制。
- 崩溃恢复。
- journal 和 inner stream 快照备份。
- 隐私审计日志。

验收：

- 长时间运行不会疯狂刷 token。
- 异常后可以恢复当前活动和内在状态。
- 一天结束后能复盘输入、行动、记忆和状态变化。

## 当前建议优先级

近期只做阶段 1 到阶段 3。不要太早接 QQ、社区、视频和游戏，否则会在内在连续性尚未稳定时引入高噪声和高权限风险。

第一版最小闭环应是：

```text
text InputEvent
  → DialogueOrchestrator 快速反应
  → InnerStreamLoop 异步吸收
  → ActivityJournal 记录
  → memory_events 周期沉淀
```
