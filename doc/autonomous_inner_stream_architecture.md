# 自主内在叙事流架构设计

本文档描述一个以“内在叙事流”为核心的自主系统设计。目标不是让角色模拟人类行为，而是让角色在持续的信息输入、行动输出和记忆沉淀中形成可延续的心理状态、兴趣和未完成感。

## 核心定位

系统中的人类、网页、屏幕、聊天软件、视频、游戏、时间变化都属于外部信息输入。人类不是默认中心，也不是命令发出者；他说话只是高信息密度输入源之一。

角色可采取的输出也不只有回复人类。输出可以是说话、沉默、继续阅读、搜索、写笔记、打开应用、切换网页、继续看视频、玩游戏或什么也不做。

```text
信息输入源
  语音 / 文本 / 屏幕 / 网页 / 消息 / 视频 / 游戏 / 时间
        ↓
输入事件总线
        ↓
        ├─ 快速反应路径：判断是否说话、短应、沉默或稍后回应
        ├─ 自主行动路径：判断是否继续当前活动、切换活动或待机
        └─ 内在叙事流：异步吸收输入和自身行动结果，维护心理连续性
```

内在叙事流不是所有行为的前置条件。即时对话可以先走快速反应路径，内在叙事流随后并行吸收这次输入和输出结果，避免语音延迟。

## 信息输入层

信息输入层采用类型注册机制。每种输入源注册为一种 input type，统一产出 `InputEvent`，由事件总线分发给内在叙事流、对话调度器和未来的自主行动系统。

最基础、必须优先实现的是纯文本输入类型。其他输入源都可以先降级为文本摘要，再接入同一套事件机制。

### InputEvent

建议事件结构：

```json
{
  "id": "event id",
  "type": "text",
  "source": "speech",
  "timestamp": "2026-05-21T12:30:00+0800",
  "content": "输入正文或摘要",
  "metadata": {
    "speaker": "可选说话者",
    "foreground_app": "可选前台应用",
    "confidence": 0.92
  },
  "privacy": {
    "private": false,
    "reason": ""
  },
  "priority": "low|normal|high|urgent",
  "lifetime": "ephemeral|session|memorize_candidate"
}
```

字段含义：

- `type`：输入类型，例如 `text`、`screen`、`web_page`、`chat_message`、`media`、`game_state`、`time_tick`。
- `source`：具体来源，例如 `speech`、`qq`、`edge`、`bilibili`、`system_clock`。
- `content`：给 LLM 阅读的自然语言内容。非文本源必须先摘要成文本。
- `metadata`：只放辅助判断信息，不放必须解析的业务规则。
- `privacy`：隐私检测结果。隐私事件可以进入“知道有隐私输入出现”的弱信号，但不能注入正文。
- `priority`：输入强度。它不是命令，只是提示当前输入的打断价值。
- `lifetime`：事件生命周期，用于决定是否进入 journal 或记忆候选。

### 类型注册

每种输入类型注册一个 handler：

```text
InputTypeRegistry
  ├─ text
  ├─ screen
  ├─ web_page
  ├─ chat_message
  ├─ media
  ├─ game_state
  └─ time_tick
```

handler 职责：

- 接收原始输入。
- 转换成统一 `InputEvent`。
- 做必要的隐私过滤和摘要。
- 标注来源、时间、优先级和生命周期。
- 不直接决定角色应该做什么。

### 最小文本类型

`text` 是第一阶段的基础类型：

```json
{
  "type": "text",
  "source": "speech",
  "content": "刚才听到的一段话",
  "metadata": {
    "speaker": "人类参与者",
    "is_direct_address": "unknown"
  },
  "priority": "normal"
}
```

直接称呼、提问、强情绪、求助、危险提示等可以提升 priority，但仍不代表必须回应。是否回应由快速反应路径判断。

## 事件总线

事件总线负责分发输入，不负责解释输入。

```text
InputEvent
  ├─ DialogueOrchestrator：快速判断说话与否
  ├─ InnerStreamLoop：异步吸收为心理连续性
  ├─ ActivityLoop：未来判断自主行动
  └─ ActivityJournal：记录有价值事件
```

用户语音进入后应并行分发：

```text
speech text event
  ├─ DialogueOrchestrator 立即判断是否回应
  └─ InnerStreamLoop 延迟 1-3 秒合并相关事件后更新
```

如果角色回应了，需要追加自身行动事件：

```json
{
  "type": "self_action",
  "source": "speech_output",
  "content": "我刚才选择回应，并说了：...",
  "metadata": {
    "action": "speak",
    "reason": "快速反应路径认为这句话需要接住"
  }
}
```

如果没有回应，也应追加或合并为：

```json
{
  "type": "self_action",
  "source": "dialogue_orchestrator",
  "content": "我感知到这段话，但判断它更像背景、自言自语或未完成表达，所以没有打断当前活动。",
  "metadata": {
    "action": "silence"
  }
}
```

## 内在叙事流

内在叙事流维护“我现在作为我还在想什么”。它不应是计划表、兴趣权重表或程序可解析规则，而是稳定栏目化的自然语言心理状态。

建议输出格式：

```text
【当前心境】
此刻整体心理状态和精力形态。

【注意力焦点】
自然牵引我的对象、话题或活动，不限于人。

【外部输入态势】
最近进入的信息流有哪些，它们是强输入、弱输入、背景输入还是可忽略输入。

【未完成感】
没看完、没查完、没说完、没想明白、没玩完或还想回头看的东西。

【行动倾向】
如果接下来没有更强输入打断，我自然倾向继续、切换、等待、观察、说话或行动。

【克制与边界】
现在不该做或不必做的事，例如打断别人、碰隐私、频繁切换、把背景信息当召唤。
```

这个结构供 LLM 阅读，不供 Python 解析成 if/else。程序可以整体注入这段文本，但不应根据栏目内容写硬编码逻辑。

## InnerStreamLoop

内在叙事流应脱离单次对话，由循环维护。

触发来源：

- 输入事件：文本、语音、网页变化、屏幕变化、外部消息、时间 tick。
- 自身行动：说话、沉默、搜索、阅读、写笔记、看视频、玩游戏、切换活动。
- 活动阶段：开始、暂停、继续、完成、放弃。

更新策略：

- 对话不等待内在叙事流更新，避免语音延迟。
- 用户或其他人说话后必须进入事件队列，但可以异步合并后更新。
- 连续输入应短窗口合并，避免每句话都刷一次 LLM。
- 隐私内容不进入正文，只记录“出现了不适合读取的输入”。
- 没有实质变化时可以保留旧流并轻微修正。

建议频率：

- 普通空闲：3-5 分钟一次。
- 活跃浏览/搜索：1-2 分钟一次，或页面变化后延迟 20-40 秒。
- 集中活动：10-20 分钟一次，活动阶段变化时额外更新。
- 长时间无人互动：逐渐降频到 15-30 分钟。
- 夜间或低活动时段：30-60 分钟一次。

## ActivityJournal

自主系统需要记录角色做过什么，否则行为不会沉淀为经历。

`activity_journal` 是自然语言事件流水，不是计划表：

```json
{
  "timestamp": "2026-05-21T15:20:00+0800",
  "kind": "read_page",
  "summary": "阅读了一篇关于本地向量记忆压缩的页面，注意到 Qdrant 数据膨胀可能影响长期运行。",
  "inner_effect": "这让我更在意记忆系统的清理策略，想之后查一下压缩和去重。",
  "memory_candidate": true
}
```

后续可由 `memory_events` 抽取为长期事件，由 `cognition` 吸收为稳定认知。

## 与现有模块的关系

- `memory`：记录发生过什么，包括对话事件和自主行动事件。
- `cognition`：记录长期稳定认知，例如对人、作品、项目、关系、自我的判断。
- `emotion`：可保留给表情、VTS 和短期情绪兼容路径。
- `inner_stream`：记录当前还在想什么、想靠近什么、想避开什么、什么没完成。
- `dialogue_orchestrator`：快速判断是否说话、短应、沉默或稍后回应。
- `activity_loop`：未来基于内在叙事流和环境判断是否行动。

## 提示词方向

system prompt 应强调：

- 你不是任务规划器，不输出待办清单。
- 你维护的是持续主体的当前心理状态。
- 你可以产生行动倾向，但不要写成强制计划。
- 所有人、网页、消息、屏幕、时间都是输入源；没有任何输入天然是中心。
- 说话只是可能行动之一，沉默和继续当前活动同样有效。
- 区分短期刺激、持续兴趣和长期认知。
- 保留未完成感，它是自主连续性的关键。
- 不要把工具能力误认为必须使用工具。

user prompt 应按输入块组织：

```text
【当前内在叙事流】
...

【时间与运行状态】
...

【最近输入事件】
...

【最近自身行动】
...

【当前环境摘要】
...

【相关长期记忆】
...

【认知与情绪】
...

【可用行动边界】
...

【这次触发原因】
...
```

## 设计原则

- 程序提供身体、边界和记忆，不替角色写具体生活计划。
- 输入统一事件化，不把人类语音特殊化为必答请求。
- 内在叙事流异步维护，不阻塞快速反应。
- 角色自身行动必须回写为经验。
- 长期自主性来自经历沉淀，而不是随机事件或固定日程。
