# Emotion 迭代指南

## 情绪层的定位

Emotion 存储的是**浅层情绪基调 + 中期动机**。它是短期态（数轮到十几轮），与 cognition 的长期态和 character card 的底色明确区分。

三层边界：

| 层 | 时间尺度 | 内容 | 示例 |
|---|---|---|---|
| character card | 永久 | 底色性格 | "知性冷静，说话有条理" |
| cognition | 持久（跨 session） | 稳定印象 | "真冬对咖啡拉花有兴趣" |
| emotion | 短期（数轮） | 当前状态 | "因为对方持续敷衍而不太开心" |

## 评估流程

每轮对话后异步调用：

```text
emotion.evaluate(user_text, assistant_text, character_name)
  │
  ├─ system: "你是{name}的情绪层维护器..."
  │
  ├─ user: 当前情绪 + 本轮对话
  │
  ├─ → LLM 输出两行:
  │     情绪基调：<value>
  │     中期动机：<value>
  │
  └─ 更新 self.tone / self.motivation
```

### 稳定性规则

1. 情绪基调可以随对话变化，但不因为一句普通话剧烈翻转
2. 中期动机比情绪更稳定，通常持续数轮
3. 如果上一轮情绪/动机仍然合理，应保留并轻微修正
4. 只有对话完全没有可感知情绪色彩时才留空

### 输出约束

- 每项最多一句，短而具体
- 没有明显内容时可留空，但不要偷懒
- 格式固定两行，不要多余文字

## 情绪->立绘/VTS 联动

当 `emotion._on_update` 回调被设置时，情绪变化会驱动：

- **立绘**：`portrait_controller` 根据情绪基调调整表情选择
- **VTS**：`VTSExpressionArbiter` 根据情绪基调叠加面部表情层

## 常见问题

### "把短期烦躁写成了永久人格"
emotion 的 tone 如果几轮不重置，可能被 LLM 持续强化。检查点：
- 是否多轮没有主动重置/修正 tone？
- 是否把 tone 写成了 "性格易怒" 而非 "当前心情不好"？

### "情绪在空对话中也波动"
如果用户只说"嗯""好"等短确认，emotion 本应保持或轻微修正。如果剧烈变化，说明评估 prompt 的"稳定性规则"需要加强。

### "情绪基调持续堆积不衰减"
当前 emotion 没有主动衰减机制——它只在新评估时修正。如果多轮不触发 evaluate（异步线程拥塞），可能需要增加一个基于时间的衰减。

### "Emotion 污染了回复内容"
emotion 属于 ChatSession.build_messages() 注入的 system message 之一，只影响语气倾向。如果发现回复直接引用 emotion 内容，需要在 system prompt 中禁止对情绪状态的元讨论。

## 测试用例

```text
用例 1：情绪跟随
  用户持续夸奖 3 轮 → tone 应偏向正面
  用户持续批评 3 轮 → tone 应有所反映

用例 2：情绪稳定性
  用户夸奖一句后马上切换到普通提问 → tone 不应剧烈变化

用例 3：空评估
  用户只说"嗯" → tone 应保持或轻微修正，不应清空或大幅变化
```
