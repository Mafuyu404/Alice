# Emotion 迭代指南

本文档记录 Alice Chat 情绪层的目标、边界、测试方式和本轮迭代记录。它用于提示词和行为迭代，不是普通用户说明。

## 定义

Emotion 是当前对话状态层，包含两部分：

- `情绪基调`：浅层、当前可感知的情绪色彩。
- `中期动机`：接下来一小段时间内想做的事。

保存位置：

```text
characters/{id}/emotion.txt
```

格式固定为纯文本：

```text
情绪基调：...
中期动机：...
```

## 与其他层的边界

适合 emotion：

- 对方一直敷衍，Alice 有点不高兴。
- 对方认真夸奖，Alice 轻微开心。
- 对方情绪低落，Alice 想让对方重新振作。
- 对方正在做人格测试，Alice 想配合完成测试并保持严谨。

不适合 emotion：

- 长期偏好和人物印象，应进入 cognition。
- 可检索事实和事件，应进入 memory。
- 当前网页内容和屏幕内容，只能作为情绪判断材料，不应直接写入 emotion。

## 稳定性要求

情绪基调比中期动机更轻、更容易变化，但不应该因为一句普通话剧烈翻转。

中期动机应持续数轮。只有以下情况才应明显改写：

- 原目标已经完成。
- 原目标明显失败或不再适用。
- 对话出现更强的新目标，例如用户突然情绪低落、焦虑、明确求助。

不合格表现：

- 每轮都清空 emotion。
- 每轮都换一个完全无关的动机。
- 情绪强度过高，压过用户的问题。
- 情绪和动机只被保存，但完全不影响下一轮回复。

## 测试标准

每轮测试必须是完整对答：

```text
User: ...
Alice: ...
Emotion evaluation:
情绪基调：...
中期动机：...
```

本轮测试采用三轮迭代，每轮 40 次用户输入和 40 次 AI 回复。每次对答后都同步评估 emotion，并在下一轮构造消息时注入 emotion context。

必须检查：

- AI 能否在被夸奖、被敷衍、用户沮丧、用户认真测试时产生合理情绪。
- AI 能否产生中期动机，而不是只写情绪。
- 情绪和动机是否影响下一轮回复方式。
- 情绪和动机是否稳定：既不会一轮一清，也不会在明显场景变化后僵死。

## 测试命令

```bash
python tests/run_emotion_dialogue_iterations.py
```

日志输出：

- `logs/emotion-dialogue-round1.md`
- `logs/emotion-dialogue-round2.md`
- `logs/emotion-dialogue-round3.md`

日志包含完整 40 次对答、每轮注入的 emotion context、每次 emotion evaluator 的 prompt 和输出、写入后的 emotion 文本、最终判断。

## 三轮迭代计划

### 第一轮

前置优化：

- 将 emotion 存储从 JSON 改为纯文本 `emotion.txt`。
- evaluator prompt 明确定义情绪基调和中期动机。
- 要求每次对话后都进行评估。

重点观察：

- 能否在 40 次对答中正确产生情绪和动机。
- 情绪 context 是否进入下一轮聊天 prompt。

### 第二轮

前置优化：

- 强化稳定性规则：情绪可轻微变化，中期动机应持续数轮。
- 要求保留仍然合理的旧动机，只在目标完成、失败或更强目标出现时改写。
- 补充基调清空规则：稳定、收束、普通提问不等于没有情绪；活跃测试中应保留低强度但具体的基调，例如平稳、专注、轻微愉悦或轻微受挫。

重点观察：

- 动机是否不再一轮一换。
- 用户情绪低落时，动机是否转向支持和振作。
- 收束阶段是否避免把情绪基调过早清空。

### 第三轮

前置优化：

- 强化“情绪影响回复但不覆盖问题”的规则。
- 检查 Alice 是否能在回复中体现当前情绪和动机，同时仍回答用户问题。

重点观察：

- 被夸奖后的回复是否更柔和。
- 被敷衍后的回复是否稍微收紧但不失控。
- 用户低落时是否主动扶持。
- 测试结束时情绪和动机是否回到合理状态。
