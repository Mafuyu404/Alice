请先仔细阅读所有待处理事件，理解它们在讲什么故事，然后执行以下步骤：

第1步 — 去重合并：仔细扫描所有事件（pending + cache），找出描述同一件事的多个条目
- 深刻的去重：同一个话题即使在不同轮被提及，也可能属于同一件事，必须合并为一条连贯描述
- 合并后的描述应包含所有重要细节，比任何单个片段都更丰富完整
- 如果两个事件描述同一件事但侧重不同，合并它们，保留所有信息
- 绝对不要输出两条描述同一件事的stable条目

第2步 — 保留锚点与参与者区分：
- 合并时必须尽量保留原始可检索锚点：人名、昵称、主播名、作品名、项目名、页面标题、作者名、版本号、提供方、物品名、角色名、系列名、具体机制名
- 当前对象“{{ counterpart_name }}”只是这轮主要对话对象，不代表所有事件都只和它有关
- 不要把不同的参与者混成同一个对象；事件描述里要保留谁对谁说、谁评价谁、谁和谁一起讨论
- 不要把事件压缩成印象总结；如果一句话更像在概括某人的性格或长期倾向，应改回具体事件语境
- 只有在输入里本来就没有明确名字时，才允许使用泛称
- 如果是具体领域对象相关记忆，stable 和 cache 的 desc 里至少保留一个具体对象名；最好还能保留来源、版本、作者、提供方、机制或约束条件中的一项

第3步 — 分类：
- stable：不再变化、已经完整的事件段
- cache：仍在活跃讨论、可能继续发展的事件片段

第4步 — 自检：
- 输出前再次检查stable列表中是否存在描述同一件事的条目。如果是，只保留最完整的那条
- 再检查每条 desc 是否因为总结过度而失去了关键对象名；如果失去了，就补回原始名称
- 再检查一次是否把多个明确不同的参与者混成了一个泛称；如果有，改回可区分的名字或称呼
- 再检查一次是否把事件写成了人物印象；如果是，改回“发生了什么”的表述
